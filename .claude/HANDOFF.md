## 不変条件（壊すと困る）

- 座標は 2 種類。V は画面のデバイスピクセル（client × dpr。入力、live / pred）、S は面のピクセル。S = V × sk + (sox, soy)。sk・sox・soy は onDown の `mapNow()` で 1 回だけ求め、ストローク中は変えない。スクロール位置は必ず `origin()` を通して読む（画面に固定の間は入れた時の fx / fy を返す）。押していない間（ホバーなど）に sox / soy を使うときは、先に mapNow() を呼ぶ（最後に押してからスクロールしているかもしれない。T-048）。面の密度 `sdpr` は起動時の dpr で固定し、表示タイルの大きさ DT もそこで決まる。
- 面を変える操作は必ず `push(R, atlas, b)` で履歴に積む（R は S 座標、b は描いた物の外接矩形で、選択ツールのクリックで使う。消しゴム・全消去・選択の削除は b なし）。R の矩形は重なってもよいが、アトラスの画素はどの矩形も同じ時点（その手の前）の状態にそろえる。面に描くのは必ず R の中だけ（R の外に描いた画素は元に戻しても残る。T-044 で塗りつぶしの 1px の膨張が画面の外へはみ出していた）。描いた範囲 `cb*` は push / swap で広げ、clearAll で空にする。塗りつぶしの読み戻し範囲と全消去が積むタイルがこれに依存している（画素は cb* の中にしかない）。全消去は、直前の手が全消去（履歴の手の `clr`）か、cb* が空で文字もなければ何もしない（T-058）。直前の手が描く手（b がある）でなく文字もなければ、hasInk で cb* に掛かるタイルを読み戻し、画素がなければ何もしない（T-063。消しゴム・選択の削除・最初まで元に戻した後）。b は描く手（線・図形・塗りつぶし・選択の移動）にだけ付ける決まりなので、新しい手を足すときも守る。
- 消しゴムでは `markBox` / `markSeg` を `erasePts()` より前に呼ぶ（削る前のタイルを退避するため）。
- 文字の物は面の要素（.to）で、状態は [文字, x, y, 大きさ, 色, 濃さ]（S の px、CSS px の整数に丸める）。状態を変えるのは必ず `tApply(物, 状態)`（null で外す）で、その前の状態を履歴の手の `t` に [物, 前の状態] として積む。undo / redo は `swapAll` が画素（c があれば swap）と文字（t があれば swapText）を両方入れ替える。
- インストールページで選んだ既定は、コードの中の文字列 `'__PAINT_DEFAULTS__'` を JSON の文字列に置き換えて渡す（`DEF`）。terser は JSON.parse の引数を畳まないので、この文字列は圧縮後もそのまま残る（変えるときは dist で確かめる）。
- 設定は「組み込み → DEF（インストールページ）→ サイトの保存」の順に重ねる。サイトに書くのは、組み込み＋DEF からの差分だけ（`base` と比べる）。保存は remember() から 400 ms 後にまとめて行い、hide の前には待たずに済ませる。起動中（`ready` が立つ前）の setColor などは保存しない。
- 入力中の文字（`ta`）と浮いている選択（`sel`）は、面や履歴を変える操作の前に `settle()`（commitText + dropSel）で確定する（undo・redo・clearAll・exportBlob・togglePass・hide。onDown と setTool は道具に応じて片方だけ）。新しく面を変える操作を足すときも同じにする。選択が浮いている間は、元の範囲が面から消えていて履歴とずれている。文字の入力欄のイベント（TA_STOP）はページへ渡さない。
- 入力のホットパス（onMove 以下）では、オブジェクトの割り当ても DOM の読み書きもしない（例外は開発用の入力の録画を入れている間だけ。録っていなければ recCur の比較 1 回）。面のタイルの読み戻しもしない。`now()` を呼ぶのは HUD を表示しているときだけ。erasePts は `ePts`（Float64Array）と既存タイルのループだけで動く。
- live / pred の W / H は縮めない（fit は大きくなるときだけ作り直す）。面は `sizeSurface()` で文書の大きさに合わせる（縮むこともある。タイルは消さず、clip で隠れるだけ）。
- 描画中（`act !== -1`）は fit・undo・clear をしない。fit は `pendingFit` で後回しにする。
- 確定の受け渡し: commitLive はタイルに描いたのと同じフレームでグループの opacity を 0 にし、live は 2 フレーム後に `finishHandoff()` で消す。次の onDown・undo・redo・fit は先に finishHandoff を呼ぶ。受け渡し中は liveAlpha が opacity を戻さない。
- 半透明の線（T-056、blend が既定の 'canvas'）: ペン・蛍光ペンは live に線の濃さで描く。stk() が、新しい部分の所を destination-out で抜いてから lighter・globalAlpha = sA で足す（濃さ = sA ×（今までの形 ∪ 新しい部分）。不透明で重ねてから濃さをかけるのと同じ計算）。pred は globalAlpha = sA で描き、drawTail の最後に cutPred が、描いた部分の形（addPiece で覚えた区間。輪 RN = 16384 個、RB = 32 個ずつの外接矩形で絞る）を destination-out で抜く（live と重ねても、縁のぼかしの数画素を除いて sA を超えない。live は区間ごとの確率的な和、抜く形は 1 回の stroke の幾何的な和なので、縁だけ少し抜き足りない）。図形は live に直接 sA で描く（毎回描き直すので重ならない）。確定は live をそのまま（sCa = 1）面に合成する（前の方式と 8 ビットの丸めで 3 以内）。まとめた要素（.g）の opacity は 1 のまま（確定の受け渡しで 0 にするのは同じ）。前の方式（'group'）では live / pred に不透明で描いて .g に opacity をかけ、liveAlpha が押す前に合わせておく（描き始めの 1 フレームが濃くならないように）。どちらの方式も壊さない。描いている途中にキャンバスからキャンバスへ drawImage しない（コピー元を描き換えると、スナップショットの分だけキャンバス全体のコピーが走る）。unbounded な合成（destination-in・source-in・copy など）も canvas 全体に効くので、入力のたびには使わない。
- scroll / wheel のリスナーは登録しない（テストで確かめている）。スクロールはブラウザに任せる。
- パネルは同時に 1 つだけ。閉じるのは wrap の pointerdown（capture）・Esc・hide。capture のリスナーはパネルが開いていなければ比較 1 回で戻る。パネルはバーの子（absolute）なので、バーの幅（measureBar）には入らない。
- innerHTML・style 属性・外部リソースは使わない（CSP と Trusted Types への対策）。
- 2 回目の実行は表示の切り替えだけ（`window.__paintBookmarklet` で判定）。閉じた後の取り消し待ち（`byeT`）の間は、show / toggle が reopen になる。Esc と「−」は hideHint で隠し、HINT_MS（4 秒）の間「ブックマークレットで再表示」を出す（`hintT`。close の取り消し待ちと同じく、お知らせ以外は消えて入力のリスナーも外れている）。show・close・destroy は先に endHint を呼ぶ。ブックマークレットと API の hide はお知らせを出さない。
- × は `close()`（描いた物があれば BYE_MS = 8 秒の取り消し待ち。その後に destroy）。API の `destroy()` はすぐに解放する（テストで確かめている）。取り消し待ちの間は visible = false で、入力のリスナーも外れている。

## 決定事項と理由

- シンプル版（T-071、research/simple。ユーザー: 開いた時に見る UI をシンプルに。コードは必要以上に削らなくてよい）: ツールバーにはペン・元に戻す・その他（⋯）・隠す（−）だけを並べる（色と太さのボタンは T-074、消しゴムのボタンは T-076 で外した。ペンの太さの既定は 6。本家は 4）。お知らせは押せるボタンの付いた物（隠した後の「再表示」と閉じた後の「元に戻す」）だけを出す（T-074。say() の先頭で fn のない物を捨てる）。スマホでは 2 本指でスクロールする（T-074。twoDown / twoMove / twoUp を pad の onDown などより先に登録し、タッチが 2 本になったら描き始めた線を abortStroke で捨てて、2 本の中点の動きで scrollBy。2 本とも離すまで描かない。scroll / wheel のリスナーは今も登録しない）。ほかのボタン（選択・蛍光ペン・図形・文字・塗りつぶし・やり直す・ページ操作）も作るがバーには入れない（ショートカットは今まで通り効く）。その他のメニューは全消去と閉じる（×）だけ（T-072、ユーザーが画像で示した。開発用を入れていても同じ）。ほかの項目（背景・保存・コピー・電卓・画面に固定・デフォルトの変更・開発用）も item() で作ってから moreP から外す（キーは効く）。インストールページの開発用「ツールバーにすべてのボタンを出す（本家と同じ）」（DEF.fullBar、既定は切り）で本家のバーとメニューに戻せる（見比べるため。入力の録画など開発用の項目もこのときだけ出る）。ペンのボタン 1 つで、押すたびにペンと消しゴムが入れ替わる。印（penD）と名前も今の道具に変える（markPen。syncTool・togglePass・syncPen から呼ぶ。E キーで消しゴムにしても変わる）（T-076、ユーザーの要望: ペン一ボタンでマークごと切り替わる感じ。経緯は T-073 で 2 回押しをページ操作にし、T-075 でペン → 消しゴムにしたが、意図は 1 つのボタンでの切り替えだった）。ページ操作モードはない（T-077、ユーザー: いらない。V キーも fullBar のときだけ効く。操作の一覧の V の行は 3 つ目を 'full' にして、ツールでは fullBar のときだけ出し、build.mjs はインストールページに出さない）。種類のパネルは出さない（パネルの印 .dd も付けない）ので、シンプル版ではペンの種類を選べない。すべてのボタンやメニューを使う既存のテストは fullBar で起動する（freshFull）。何を残すか（予測線など）は「後で、すぐに決めることではない」とユーザーが言ったので、今は UI だけ

- 絵はページに貼り付ける（T-003、ideas/scroll-follow.md の方式 B）。確定した絵はページ座標の canvas タイル（面）に描き、スクロールはブラウザの合成に任せる。ページ全体の大きさのキャンバス 1 枚（方式 A）は長いページでメモリと上限に当たり、スクロールのたびに JS で動かす方式（C）は絵が 1 フレーム以上遅れるので捨てた。
- 画面に固定（T-016、ユーザーが作ると決め、その他のメニューに置いた）: 入れると、面をその時のスクロール位置（fx, fy）のまま position: fixed（left = hdx − fx）にする。スクロールで JS が動かないのは同じ。切るときは、今見えている位置のままページに付け直す: スクロールした分 Δ を S にして shiftAll で面のタイルを描き直し（切る時だけ描いた量に比例する）、履歴の矩形・外接矩形・文字の状態をずらす。文字は CSS px の整数のままずらす（sdpr が整数でないと、線との差が 1 デバイス px 未満出ることがある）。文書の上や左にはみ出した所は消える。固定の間は hdx を測らない。固定にする前のページの位置へ戻す案（切ると絵が飛ぶ）と、面の原点をずらし続ける案（文書の上端側に描けない所ができる）は捨てた。サイトごとには覚えない。
- 描いている途中の線（live / pred）は画面に固定のまま。入力の経路と遅延を一切変えないため。代わりに描画中のスクロールには追従しない（開始時の位置に確定）。
- 表示タイルは約 256 CSS px（DT = 128 × max(2, round(sdpr × 2)) デバイス px）。512 px だと初めて触れたときの確保が @2x で重く、128 px だと要素数が増える。履歴タイル 128 の倍数なので、履歴タイルが表示タイルをまたがない。
- 表示タイルは desynchronized にしない。数が多いと低遅延の経路が重く、合成の順序も live とずれる。ちらつきは受け渡し（2 フレーム後に live を消す）で防ぐ。
- 面の密度は起動時の dpr で固定する。表示倍率を変えても絵を作り直さず、sk で座標を換算する（ブラウザが拡大縮小して表示する）。
- 面は documentElement 直下の absolute 配置で、html のずれ（margin・border・position）は getBoundingClientRect から求めた hdx / hdy で打ち消す。contain: strict と overflow: clip で、はみ出してスクロール範囲を広げない。
- 範囲外にしたもの: ページ内の一部だけがスクロールする要素（Gmail など。T-017 の候補）、描いた後に本文が動くことによるずれ。
- スマホ（1 段に収まらない幅）では、ツールバーを 2 段に整える（T-064、ユーザーが「2 段に整える」を選んだ。1 段に収める〈選択・塗りつぶしなどをその他へ〉・縦に並べる案ではなく）。上の段に選択〜塗りつぶし、下の段に色と太さ・元に戻す〜閉じる（T-067、ユーザーの要望で色と太さを下の段に移した）。ボタンと並びは PC と同じ。幅は決め打ちせず、fit の layBar が折り返すか（閉じるボタンと選択ボタンの offsetTop）を測る（1 段の幅はマウスで 492px、タッチは .b が 38px なので 604px）。2 段のときはツールバーの幅を長い方の段に合わせる（bar.style.width）。キーのない端末（hover: none）では起動のお知らせを「− で隠す」にする。viewport の指定がないページでは、スマホは 980px 幅で描いて縮めるので 1 段のまま小さく見える（T-011 に残した）。
- ツールバーは「よく使う物だけバー、残りはパネル」にした（T-004、幅 1,159px → 446px）。図形は最後に使った物を出す 1 つのボタン、色・太さ・濃さは点のボタン 1 つ、全消去・背景・保存・コピーは名前とショートカット付きのメニュー。色替えはクリックが 1 手増えるが、数字キーは残る。不便なら最近の色をバーに出す案を検討する。縦置きや折りたたみは、幅が十分に縮んだので見送った。
- 文字（T-009、T-019）は、入力中は本物の textarea（IME のため）、確定したら DOM の「物」（方式 C でユーザーが選んだ）。物にしたので、拡大縮小は文字の大きさを変えて描き直す（ぼやけない）、書き直しができる、四角と中の文字を別々に動かせる。代わりに文字は常に線より手前に出て、塗りつぶしは文字を壁にしない。書き出しは paintText で fillText し、基線は CSS の half-leading と同じ計算（CSS px の書体の寸法を整数に丸め、余白は切り捨て）。入力欄・DOM・書き出しのインクの外接矩形が 1x・1.5x・2x、13〜48px で一致した（2x・13px の下端だけ 1 デバイス px）。書体は 600 の system-ui、大きさは太さのスライダーと共用。書き直すときは、その物の色・大きさ・濃さを今の設定として拾う。
- 文字に触れる（T-022、ユーザーの提案。`touchText`、既定は入り）: TOUCH の道具（ペン・蛍光ペン・図形・塗りつぶし）で、選んでいる物か文字の上を押したら selDown に回す（選択ツールと同じ動き）。外を押したら選択を外してその道具で描く。消しゴムと文字ツールは対象外。選んでいる文字をもう一度押して動かさずに離すと書き直し（sWas）で、ダブルクリックもこれになるので dblclick のリスナーは外した。書き直しの書式は入力欄だけが持つ（taFs / taC / taA）ので、道具と今の色は変わらない。入力中に色を選ぶと文字にも反映し、大きさ・濃さは文字ツールのスライダーを動かしたときだけ反映する。入力中に外を押すと、どの道具でも確定だけ（線は描かない）。
- 隠したとき（Esc・「−」）は「ブックマークレットで再表示」を 4 秒出し、「再表示」を青い押せる文字にする（T-008。文面はユーザーが決めた。案内のお知らせは「Esc で隠す」と同じ「〜で〜」の形でそろえる）。隠している間に画面の隅へ戻すボタンを置き続ける案と、キーを待ち受けて戻す案は、ページを覆う・ページのショートカットとぶつかるので捨てた。
- 「−」は絵ごと隠す（Esc と同じ）。T-025 でユーザーの要望どおり「＋」1 つにたたむ形にしたが、使ってみたユーザーが「合っているが、元の方がいい設計だった」としたので T-033 で戻した（「＋」・setMini・その他のメニューの「隠す（絵も）」も外した）。広いツールバーを標準にする案と横幅を広げるボタンは、ユーザーが「だいぶ却下」としたので作っていない。
- ツールバーはどこを押しても、4px 以上引けば移動（T-026、ユーザーの要望）。動かし始めるまでポインタを奪わない（奪うとクリックの対象がバーになり、ボタンが押せなくなる）。引いて離した後のクリックは `eatClick` の印で 1 回だけ捨て、印は次にバーを押したときに消す（タイマーで外すと、次のクリックが早いとそれまで捨ててしまった）。パネルの中（スライダー）は対象外。
- 電卓（T-029、ユーザーの idea2）: その他のメニュー（とインストールページ）で入り・切り、既定は切り、サイトごとに覚える。入りのとき、カーソルのある行が計算式なら薄い答え（.gh、行の幅の後ろ）を出し、Tab で書き込む（execCommand の insertText なので入力欄の Ctrl+Z が効く）。Tab は答えがなくても preventDefault する（入力欄からフォーカスを外さない）。計算は calcLine の再帰下降（eval なし）。NFKC で全角を半角にし、× ÷ − を置き換え、桁区切りのカンマを外す。数字の後ろに演算子がある行だけを式とみなす（「12」「-5」では出さない）。日付（2026-10-15）も式として答えが出るが、電卓は既定で切りなので受け入れた。答えの空白は式に合わせる（T-045、ユーザーの要望。演算子か = の前後に空白があれば「 = 12」、詰めた式なら「=12」、= で終わる行は答えだけ。最後に打った空白には重ねない）。答えが出ている間は、入力欄の点線の枠を答えの右端（ghostR）まで広げる。行の幅は見えない入力欄（mta、測る間だけ wrap に置いて外す）の scrollWidth で測る。canvas の measureText や span は、書体によって「*」の組み方が入力欄と変わって数 px ずれ、Tab の前後で枠が跳ねたため（headless の書体で確認）。
- ペンの種類（T-028、ユーザーの idea1）: ペン・万年筆・筆・鉛筆。ペンでないときにペンのボタンを押すとペンになるだけで、ペンのときにもう一度押すと種類のパネル（普段の操作を増やさないため）。図形のボタンも同じ動きにそろえた（T-034、ユーザーの要望。それまで図形は 1 回でパネルも開いていた）。インストールページの `pickOnce`（既定は切り）を入れると、ペンも図形も 1 回で道具になってパネルも開く。touchText と同じく DEF だけの設定で、ツールの中には切り替えを置かない。太さは inkMove の点ごとの計算で、万年筆はペン先 −45° に対する線の向きの sin（0.2〜1 倍）、筆は速さ（CSS px/ms）と書き始めからの距離（0.3〜1.25 倍、離し際は 0.6 倍）。鉛筆は色ごとに 1 度だけ作る擬似乱数のかすれの模様（CanvasPattern）。種類は prefs の `pen` としてサイトごとに覚える。図形ボタンは `.shp` で見分ける（ペンのボタンにもパネルの印 `.dd` が付いたため）。
- 文字の入力欄には見えない余白 TA_PAD（10px）を付け、位置を余白の分だけ外へずらす（T-024、ユーザーの要望）。文字と点線の枠の見た目は変えずに、少し外れた所を押しても入力が続く。fitTa は余白を外して測る（Chrome の textarea の scrollWidth は左の余白だけを含み、右を含まないため）。空のときは中身の大きさが 0 になる（高さも 0）ので、少なくとも 1 行・全角 1 文字分（taFs × LH、taFs）にする（T-035、ユーザーの要望。1 文字目で枠が跳ねない）。
- 消しゴムは触れた文字の物を丸ごと消す（なぞる間は薄く、離して消す）。当たり判定は線分と外接矩形の Liang–Barsky で、入力ごとの計算に割り当てはない。薄く見せる DOM の更新は tick（毎フレーム 1 回）。
- 囲んでいる間の枠は live に描く（T-053、drawBand）。DOM の枠は 3px 動くまで出さず、スタイルの変更なので canvas より 1 フレームほど遅れて出ていた。離したら DOM の選択の枠にして、live の枠は handoff で 2 フレーム後に消す。動かす・拡大縮小する間の枠は DOM のまま。
- 選んでいるボタン（.b.on）は、重ねても押しても青い地のまま（T-054。`.light .b:hover` の方が強く、明るい見た目で地が灰色になって白い印が消えていた）。:hover や :active の規則を足すときは、.b.on より強くならないか確かめる。
- 選択（T-010）は方式 C の画素の部分（ideas/select-box.md でユーザーが C を選んだ）。浮かせた中身は面の中の canvas（selC）で、動かす間は枠の left / top / width / height だけを変える。確定は「元の範囲」と「置いた範囲」の 2 矩形を 1 手にする。動かさずに確定したら元に戻すだけで履歴は増やさない。クリックで選ぶ物は、クリックした所に画素がある手のうち外接矩形が最小の物。拡大縮小は押した所からの移動量で計算し、角は (w, h) を元の向きへ射影した倍率で比を保つ（細長い物で max 比を使うと少しの縦の動きで暴れたため）。枠は中身から外へ出して最低 24 CSS px（細い線の中央を押すと上下のつまみに当たって移動できなかったため）。
- 設定の記憶は C（R-004 でユーザーが決定）: インストールページで選んだ既定で始まり、サイトで変えた所はそのサイトの localStorage（キー `paint-bookmarklet`）に差分だけを書く。サイトをまたいで自動で共有する方法はない（保存領域はサイトごとに分かれる）ので、共通の既定はブックマークレットの中に埋め込む。差分だけにしたので、あとでインストールページの既定を変えると、サイトで触っていない所には新しい既定が効く。touchText はインストールページだけで選ぶ（ツールの中に切り替えは置いていない）。背景・ページ操作モード・計測表示は覚えない。
- デフォルトの変更（T-038、ユーザーの提案）: その他のメニューから、インストールページ（PAGE、Pages の URL を直書き）を新しいタブで開く。今のブックマークの DEF を `#defaults=<JSON>` で渡し、ページはそれをフォームに読み込んで保存し、ハッシュを `#defaults` に戻して設定の節（id="defaults"）を見せる。設定はページに集め、メニューの項目は増やさない方針（サイトをまたいで設定を共有する方法はないので、変えたらドラッグし直す）。
- 見た目の開発用パネル（T-042、ユーザーの要望: 開発用に、操作盤から操作盤の色を変えたい）: DEF.dev（インストールページの「開発用」、既定は切り）のときだけ、その他のメニューに「見た目（開発用）」を出す（ふだんのメニューは増やさない方針のため）。パネル lookP で、ツールバーの色（暗い・明るい・好きな色）・ガラス・ガウス・ぼかし・地の濃さをその場で変える（look を書き換えて applyLook）。彩度（look.sat、100〜300%、既定 180%）もここで変える（T-065、ユーザーの要望。--gs で saturate に入れる。インストールページのガラスの調整にもある）。このパネルと色と太さのパネルは、ツールバーを引いて動かす間も閉じない（T-066・T-068、ユーザーの要望: 下の色を変えて見比べるため。色と太さも既定で閉じない。ほかのパネルはインストールページの keepPanels〈動き、既定は切り〉を入れたときだけ閉じない）。keepP が閉じないパネルを決める。wrap の pointerdown ではバーの中なら閉じず、引かずに離したら閉じる。動かす間は placePanel で上下と左右を直す。「この見た目をデフォルトに」は、DEF に look を重ねて openDefaults（デフォルトの変更と同じく #defaults=）。好きな色は theme='#rrggbb' で、--bb（地）と --gc（ガラスの地）にし、相対輝度 0.3 を超えたら .light（黒い文字）。サイトごとには覚えない。
- 見た目（T-040・T-041、ユーザーが試したいと言った。インストールページの「見た目」。DEF の theme・glass・blurMode・blur・tint。既定は明るい・ガラス入り・ガウス・ぼかし 18px・地 80%・彩度 200%（T-050・T-069、ユーザーが実機で試して決めた。それまでは暗い・ガラスなしで、ガラスの重さが実機で未確認だったため切りにしていた）。彩度は T-065 で開発用に変えられるようにした）: 明るい（theme='light'）は wrap の .light で、バー・パネル・お知らせ・一覧の色を上書きする（暗い方の規則はそのまま）。ガラスは wrap の .glass で、バーとパネルの背景を消して ::before（z-index:-1）に地 rgb(var(--gc) / var(--gt)) と backdrop-filter: blur(var(--gb)) を置く（バー自体に付けると、子のパネルの backdrop-filter がバーの中しか見なくなるため）。ふつうの backdrop-filter は細長い要素だと下の文字がほぼくっきり残り、薄くなるだけだった（headless で確認。ユーザーも実機で「もっとガウス的に」と言った）。ガウス方式（.gauss、既定）は ::before を周りへ --gm（強さの 2 倍）広げて拾い、mask（角 4 つの radial-gradient と 2 本の linear-gradient、content-box）で角丸の形に切る。外側の要素の overflow や clip-path で切ると、拾う範囲も狭まってぼけが弱くなる。--gb・--gm・--gt は wrap に CSSOM で入れる（style 属性は使わない）。
- 入り・切りの項目（その他のメニューの電卓・画面に固定、インストールページの入り・切り）はスイッチの形にする（T-036、ユーザーが画像で示した）。メニューは role="switch" と aria-checked で状態を持ち、つまみ（.sw）は CSS だけで動かす。色はツールが青（#3d7cff）、インストールページはページの赤（チェックボックスのまま appearance: none で見た目だけ変える）。
- 操作の一覧（T-007、ユーザーの決定）: ? キーで画面の中央に重ねて出す。ツールバーにはボタンを置かない。中身は paint.js の HELP 1 か所に持ち、build.mjs がインストールページにも同じ物を書き出す（食い違わない。テストで両方の行を比べている）。キーは `{…}` で書き、Mac では Ctrl を ⌘ にして出す。DOM は初めて開いたときに作る。外を押すと閉じるだけで、その押下は描画に渡さない。起動時のお知らせは「Esc で隠す」だけ（T-037、ユーザーの要望。? や V は一覧で分かる）。日本語の文字列は圧縮後に \u エスケープになるので、一覧の分でブックマークレットが約 4 KB 増えた。
- ツールを選ぶ（setTool）とページ操作モードを解除する（T-021、ユーザーの提案）。ツールを選ぶのは描くつもりのときなので。色や太さの変更では解除しない。ペンと図形のボタンは、選んでいる道具をもう一度押すとパネルを開いて setTool を通らないので、ページ操作モードのときは先に setTool で戻してから、普段と同じにパネルを開け閉めする（T-057・T-062。ユーザー: 仕様の統一性）。
- 閉じる（×）は確認ダイアログではなく、8 秒の取り消し（お知らせのボタン・Ctrl/⌘+Z・ブックマークレット）にした（T-006）。お知らせの × ですぐ閉じられる（T-027、ユーザーの要望。「取り消しの可能性あり」とのことなので、要らないと言われたら外す）。確認は毎回 1 手増えるが、取り消しなら閉じる人の手間は変わらない。残り時間は CSS のアニメーションのバーで見せる（JS は動かない）。何も描いていなければすぐ閉じる。

- Delegated Ink Trail は Windows だけで使う。他の OS では API があっても OS が描かない可能性があり、その場合に予測線まで失うため。
- 蛍光ペンの予測は mpred（DEF、既定は 'full'＝ペンと同じ。'need'・'off' も）で決める（T-051・T-052・T-055・T-059。onDown で sPd・sPoly・sNeed を決める。点と点を直線でつなぐ sPoly は 'need' のときだけ）。'need' は needPred: 丸い先端が太さの半分だけ先を覆うので、1 フレーム（fi、tick で測る）後のペン先に届かない分（速さ × fi − 太さの半分、上限 40px）だけ、向きを角速度 om で回して予測する。実機の getPredictedEvents は使わない。蛍光ペンの線は点と点を直線でつなぐ（中点の曲線だと、末尾の直線が次の入力で曲線になるときに引っ込む）。経緯: そのまま描くと外れた予測が目立ち（T-051 で切った）、切るとぬるぬる感がなく、薄く描いても効かなかった（T-052）。`npm run pop` で測ると、消える画素のほぼ全部が予測だった。予測を短くする・減速で弱める・曲がりだけ考える案は、消える画素が残るか先へ伸びる分が減るので採らなかった。その後ユーザーが実機で、濃さ 35% のペンでも同じ症状が出ることを確かめ、半透明（まとめた要素の opacity）が原因らしいと分かった（T-056）。T-056 でかなり解決し、ユーザーが Chrome 標準の予測と差を感じなかったので、T-059 で既定を 'full' に戻した（'need' は開発用で見比べられる形で残した）。
- 半透明の線を canvas の中で濃さにする（T-056、ユーザーの実機の試験: 不透明のペンでは出ない先端のぴょこぴょこが、蛍光ペンと同じ太さ・濃さ 35% のペンで出た）。描いている間に濃さで変わるのはまとめた要素の CSS の opacity だけだったので、それを使わずに不透明の線と同じ経路にした。なぜ opacity で崩れるのかはヘッドレスでは確かめられない（desynchronized の canvas に opacity の祖先があると、低遅延の経路を外れて live と pred が別々のフレームで出るのかもしれない。未確認）。最初は画面大の写し（不透明で線の形を描き、変わった所を live に写す）で作ったが、写しを描き換えるたびにスナップショットの分のコピーが走り、まとめて流すベンチで入力 1 件 9.6 ms（1x）・33 ms（2x）、1 件ずつでも +0.13 ms だったので捨てた（128px のタイルに分けても 1 件 0.2〜0.3 ms）。今の形はキャンバスのコピーがなく、まとめて 12〜15 µs、1 件ずつ +約 20〜30 µs（前の方式は 5〜7 µs・64〜77 µs）。増えた分はほぼ cutPred（T-061 で測った。続いている区間は 1 本の線にして抜く）。新しい区間の所だけ抜いて濃さで重ねる（source-over）案は、区間の縁に薄い輪が出るので lighter にした。前の方式は開発用の「半透明の線の描き方: まとめて」（DEF.blend = 'group'）で残した。サイトごとには覚えない。
- 入力の録画（T-070、ユーザーが「録る機能から始めて」と決めた。T-060 の 1 段目）: 開発用（DEF.dev）のときだけ、その他に「入力を録る（開発用）」（スイッチ。入れると前の録画は消える）と「録った入力を書き出す」を出す。録るのはペン・蛍光ペンの線だけ（予測を測るため）。Chrome の予測点は本体の予測の設定（mpred など）と関係なく、入力ごとに getPredictedEvents をそのまま録る。座標は CSS px、時刻は線の押した時刻からの ms に直して書き出す（小数 3 桁）。上限は 50 万行（約 24 MB。いっぱいになったら録るのをやめてお知らせ）。ページの URL は入れない（ユーザーに送ってもらうため）。インストールページの開発用のスイッチの名前を「開発用の項目をツールの中に出す」にした。
- pointerrawupdate のリスナーは描画中だけ登録する（登録しているだけでコストがかかる）。図形は 1 フレームに 1 回で足りるので使わない。

## 落とし穴

- テストは 1 件ごとに別のブラウザのコンテキストなので、ツールが書く localStorage はテストの間で漏れない（`browser.newPage()` が新しいコンテキストを作る）。
- build.mjs のテンプレートの置き換えは、置き換え後の文字列を必ず関数で渡す。`replaceAll(目印, 文字列)` だと、コードの中の `$&` などが特殊な記号として解釈される。圧縮で変数名が `$` になった T-010（v1.5.0）から T-022（v1.7.0）まで、インストールページのボタンの中身が壊れていた（T-023 で修正）。テストは dist/bookmarklet.txt を使っていたので気づかなかった。今はビルドとテストの両方で、ボタンの href を確かめている。
- 合成した PointerEvent の timeStamp は生成時刻になる。pointerdown より前に作った move は重複として捨てられる（ベンチで一度これにハマった）。
- headless での getImageData の読み戻しは数百 ms かかることがある。時間に依存するテスト（パームリジェクションの 500ms）は、イベントを全部撃ってから検証する。
- headless Chromium は SwiftShader（ソフトウェア GPU）で動く。GPU 寄りの処理時間は実機より悲観的に出る。初回だけ遅いのはバッキングの確保が原因（→ warm）。キャンバスの確保は面積に比例して重い。
- ベンチで確定や元に戻すを測る前に、GPU の仕事を吐き出させる（`getImageData(0,0,1,1)` か `api.pixels`）。溜まったままだと、前の処理の分まで次の計測に乗って数倍に見える。@2x は特にばらつきが大きいので、2 回以上流して範囲で書く。
- テストでツールバーの上（画面の上端付近）から描き始めると、pointerdown がツールバーに取られて線が描かれない。継ぎ目の確認で一度「線が消えた」と誤解した。
- 面の画素を確かめるときは、live に残っている線を拾わないように `pixels()`（面だけ）か `screenPixel()`（画面の位置にあるタイル）を使う。確定の直後は live がまだ 2 フレーム残っている。
- この作業環境から *.github.io へはつながらない（ネットワークポリシーで 403）。公開の確認は GitHub API（Actions のジョブ結果）で行う。
- Playwright の mouse で viewport の外（負の座標）からドラッグを始めると、pointerdown がツールに届かない。
- `page.evaluate(CODE)` は CSP を通さずに実行する（Firefox のブックマークレットに相当）。本物の `javascript:` URL として実行するには `location.href = BOOKMARKLET` を使う（CSP のないページでだけ動く）。
- Artifact のビューアはダウンロードをブロックするので、そこでは PNG 保存ボタンが反応しない。
- 取り消し待ちの Ctrl+Z で reopen すると、同じ keydown の途中で onKey が登録される。DOM は配送中に足されたリスナーを呼ばないので、絵の undo までは進まない（テストで確かめている）。順序を変えるときは注意。
- 選択の動作確認で「動かしたのに位置が変わらない」ときは、まずつまみに当たっていないかを疑う（細い枠では辺の中央のつまみが中身に重なる）。テストでは `.sel b`（外枠）の矩形からつまみの位置を求める。
- `pixels()` には文字の物も入る。線の有無を画素で調べるテストでは、文字と重ならない範囲を見る（文字が動いて測る帯に入り、一度落とした）。
- ショートカットは keydown だけを止めている。keyup はページに届く（テストでページへのキーの漏れを数えるときは、ショートカットを押した後に数え直す）。
- テストの `toolOn()` は DOM の順で最初の `.b.on` を返す。図形はバーの shapeB がパネル内のボタンより先にあるので、shapeB の title（今の図形の名前で始まる）が返る。閉じたパネルの中のボタンも `element.click()` なら押せる（`[title^="PNG"]` など）。見えているかも確かめたいときは `mouseClick()` を使う。
- 起動直後や fit() の後は、暖機（warm）が setTimeout で遅れて動く。すぐに destroy すると 0 の大きさのキャンバスを drawImage してページのエラーになる（手元では間に合って通り、CI でだけ落ちていた。T-032）。destroy で warmT と rz を止めている。遅れて動く処理を足すときは、destroy で止める
- シャドウ DOM の CSS のクラス名は短く、`.g`（live のグループ）・`.p`（入力の板）・`.s`・`.t` などが全体に効く。新しい部品に同じ名前を付けると、position:absolute などが当たって崩れる（T-007 で一覧の行に `.g` を使って重なった）。足す前に CSS を grep する。
- backdrop-filter は、要素の大きさだけを元にぼかす。細長い要素（高さ 40〜60px）では下の文字がほぼくっきり残る（headless の Chromium で確かめた。ツールと関係のない素のページでも同じ）。周りも拾うには、要素を広げて mask で切る（T-041 のガウス方式）。外側で overflow・clip-path を使うと効かない。
- 画素のループの速さは、ヘッドレスでも実機と同じ（CPU）。測るときは単独で何度も回した値ではなく、本物の操作の初回（冷えた状態）で測る。単独で測った塗りつぶしの走査が速く見えたのは、たまたま囲まれた小さな領域だったため（T-047 で一度取り違えた）。2x の塗りつぶしの合計は、ヘッドレスでは GPU の読み戻しとコピーが大半で、±20 ms ぶれる。
- `fresh()` は dist/bookmarklet.txt から起動する。前の版でテストが落ちるかを確かめるときは、dist/paint.min.js と bookmarklet.txt の両方を差し替える（paint.min.js だけ替えて、前の版でも通ると一度取り違えた。T-055）。
- 合成の PointerEvent の timeStamp は、`Object.defineProperty(e, 'timeStamp', { value })` で決められる（予測・速度のテストで、計測にかかる時間で速さが狂わない）。
- テストで「ページの上にツールがかぶっていない」を見るときは、elementFromPoint が `PAINT-BOOKMARKLET` かどうかで判定する（下にあるのは本文の段落など、場所で変わる）。
