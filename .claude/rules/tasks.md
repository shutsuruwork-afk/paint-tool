# タスクの書き方

台帳は `.claude/TASKS.md` の 1 ファイル。ユーザーの依頼でリポジトリを変える作業は、小さな修正でも必ずタスクにする。質問に答えるだけで何も変えない場合は不要。

## 書式

```md
### T-NNN 見出し（ユーザーから見た結果を 1 行で）
- 状態: 次 / 進行中 / ブロック（何を・誰を待っているか） / 取り消し（理由）
- 目的: なぜ必要か。誰のどんな不便がなくなるか
- 完了条件:
  - [ ] 確かめられる形で書く（操作 → 期待する結果、追加・更新するテスト）
  - [ ] `npm test` が通り、`dist/`・`docs/` を再生成してコミットした
- 関連: ファイルと場所（`src/paint.js` の「// ---------- 履歴 ----------」節など）
- メモ: 調べて分かったこと、決めたこと、捨てた案とその理由
```

## 運用

- ID は連番で、振り直さない。やめたタスクも消さずに「取り消し（理由）」にする。
- 着手したら「進行中」へ移す。進行中は同時に 1 件まで。
- 区切りごとに完了条件のチェックとメモを更新する。セッションが途中で切れても、次のセッションがメモだけで再開できる状態を保つ。
- コミットメッセージに T-NNN を入れる（`git log --grep T-NNN` で追える）。
- 完了条件をすべて満たしたら「完了」へ 1 行（`- T-NNN 見出し — YYYY-MM-DD`）で移し、詳細は HANDOFF.md の完了ログに書く（`.claude/rules/handoff.md`）。
- 作業中に範囲が広がったら、別のタスクとして切り出す。
- 思いついた改善案は「候補」に 1 行で足す。自分の提案には「（提案）」と付ける。優先度はユーザーの指示に従う。
