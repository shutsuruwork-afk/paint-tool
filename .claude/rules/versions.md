# 版の扱い（Simple と Beta）

2026-11-04 にユーザーが決めた（T-174）。ツールには表示の版が 2 つある。描く仕組み（低遅延・面・履歴・予測など）は共通で、変わるのは見える物と一部の動きだけ（`layout()` と `cp2` の分岐）。

| コードの名前 | `cp2`（`ui: 'cp2'`） | `main`（`ui: 'main'`。前の「本家」） |

## Simple（ユーザーの領分）

- 見える物・操作・動きを変えるのは、ユーザーが指示したときだけ。Claude の案は、Beta で作って見せるか、チャットで提案する。
- 不具合の直しで、見える物と操作が変わらない物は入れてよい（直したことは報告する）。

## Beta（Claude の開発の場所）

- 新しい機能・動き・見た目は、まず Beta に入れる。Simple の見える物・操作が変わるなら、`cp2` で分けて Beta だけにする。
- 作ったら公開し、ユーザーに見せて承認を取る（何が変わったか・どう試すか。チャットと、必要なら requests.md の R-NNN）。Simple に入れるかはユーザーが決める。
- 共通の部分（描く仕組み）を変えるときは、Simple にも効くことを意識する。速さ・不具合の直しで Simple の操作が変わらない物は両方でよい。描き心地が変わる物（予測・線の形など）は、Beta だけにできるならそうし、できなければ先にユーザーに聞く。

## 開発の決まり（ユーザーが決めた）

1. 仕様に一貫性を持たせる。同じ種類の物は、同じ動き・同じ見た目・同じ言葉にする（例: ペンと図形のボタンは同じ動き。入り・切りはどれもスイッチ）。新しい物を足すときは、似た物がすでにどう動くかに合わせる。
2. 初めて使う人が気持ちよく使える。説明を読まなくても分かる並びと動きにする（説明の文で補わない。T-148）。
3. 慣れると空気のように扱える。描くことの邪魔をしない・意識させない（お知らせ・確認・余計な手数を足さない。速さを落とさない）。
