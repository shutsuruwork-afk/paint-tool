# T-131 の試作: 線を描いた命令で履歴に持つ（research/stroke-history）

2026-11-03 にユーザーが「技術的課題としてやるだけやってみて」と依頼した。`feature/paint-bookmarklet` の v1.40.0（T-149）から分けた試作で、`main` には入れていない。取り込むかは R-022 でユーザーが決める。

## 何を変えたか

- 履歴の手が持つ物を、手の種類で分けた（`src/paint.js` の「履歴」「描き直し（T-131）」節）。
  - 線・図形・消しゴム: 描いた命令 `v`（線は `RV` に 5 つずつ記録した命令の写し、図形は最後の形、消しゴムは S 座標の点の列）。
  - 塗りつぶし・選択の移動: 描いた後の画素 `f`（R と同じ並びのアトラス）。
  - 全消去: 今まで通り、面から外したタイル `d`。
- 今までの画素のアトラス `c`（描く前の画素）は、元に戻す・やり直すの近く（hpos の前後 ZHOT = 4 手）だけに持つ（`cool`）。遠い手は手放す。
- 元に戻す: `c` があれば今まで通り入れ替える。なければ `rebuild`: その手が描いた範囲（`rgn`。R を描いた物の外接矩形に絞る）を空にし、前の全消去より後（なければ土台）から、範囲に掛かる手を順に描き直す（`fwd`）。
- やり直す: `c` があれば入れ替える。なければその手だけを描き直す。
- 上限で古い手を捨てるときは、土台 `bT`（面と同じ区切りのタイル、画面には出さない）に畳み込んでから捨てる（`fold`）。土台も遠い手と同じく、何もしていないときに縮める。
- 上限を超えたら、まず描き直せる手の `c` を遠い順に手放し、それでも超えるなら古い手を捨てる（`trim`）。
- 描き直しは、描いたときの live と同じ V 座標の命令を、手ごとの大きさの canvas（`rScratch`。描いた範囲＋余白 RM = 16px）に、原点を整数だけずらして描き、確定のときと同じ写し方（`drawImage` の写し元の矩形も同じ）でタイルに写す。

## 測った数（ヘッドレスの Chromium、iPhone の UA、390×844・3x）

| | v1.40.0 | 試作 |
|---|---|---|
| 線 100 本の履歴のメモリ | 9.88 MB | 0.63 MB |
| canvas の合計 | 47.8 MB | 38.6 MB |
| 元に戻す 1 回（新しい 4 手） | 0.5〜1.6 ms | 0.6〜1.9 ms |
| 元に戻す 1 回（それより前の手） | 0.5〜1.3 ms | 0.5〜11 ms（多くは 3〜6 ms。重なった線が多いほど遅い） |
| 入力 1 件（`npm run bench`） | 6〜21 µs | 6〜20 µs（差は揺れの範囲） |
| 全画面の塗りつぶし（1920×1080 @2x） | 160〜170 ms | 240〜280 ms（描いた後の画素も写して持つため。ヘッドレスは GPU なしで写すので重く出る。実機は未確認） |

## 分かったこと・落とし穴

- 描き直しの canvas を画面大にして手ごとに消すと、タイルへの写しがまだ終わっていないので Chrome が canvas 全体を写し、3x では 1 手 7〜10 ms かかった。`transferToImageBitmap` でも、毎回作り直しても同じ。手ごとの範囲の大きさにして解決した。
- 線の端が canvas の端に近いと、canvas の大きさが違うだけで縁の塗り方が変わる（線がぎりぎり入る大きさでは、蛍光ペンの丸い端の縁が最大 10/255 濃くなった）。余白 RM で避けた。
- 原点を整数だけずらすと、線の輪郭の計算の丸めが変わり、縁の数画素が数段階違う（混ぜた 17 手のテストで最大 6/255・30 値）。原点をずらさず右と下だけを切れば完全に一致するが、遠い手の元に戻すが 3〜24 ms になったので、速い方を採った。テストは `test/memory.test.mjs` の `near`（64 値・8 段階まで許す）で比べる。
- 上限がかなり小さく（30 MB）、塗りつぶしを重ねると、土台の分だけ残せる手が減る（v1.40.0 より少ない）。縮めるのは何もしていない 1 秒後なので、続けて塗るとその前に捨てる。
- 全部のテストを流すと、T-137 のテスト（2 本指の向き）が 1 回だけ落ちた（単独で 4 回・流し直しで通った。この試作では触っていない所）。

## 取り込むなら

- `feature/paint-bookmarklet` に合わせて、TASKS.md・HANDOFF.md（不変条件の「履歴」と「スマホのメモリの上限」、決定事項、地図）を書き直す。版の `-r131` を外す。
- 残る宿題: 遠い手を続けて元に戻すとき、次の手の `c` を何もしていない間に作っておく（描き直しの待ちをなくす）。塗りつぶしの `f` を後で写す（塗った瞬間の重さを減らす）。
