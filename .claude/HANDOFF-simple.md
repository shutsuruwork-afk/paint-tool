## Simple とは

- 研究用ブランチ research/simple-cp2（0b479b5）にあるシンプル版のチェックポイント 2（CP2）を、本家の paint.js の中の「表示の版」として移した物（T-088）。
  - CP2 は別のセッションが作った。
  - 中身は、本家（v1.27.0）の paint.js に、表示と動きを変える設定（DEF.cp・fullBar）を足した物だった。
- 名前は 3 つある:
  - コードと設定の値: `cp2` / `ui: 'cp2'`
  - 画面での呼び名: 「Simple Preview」（T-090 で「Simple（Preview）」、T-101 で括弧を外した）
  - 研究用ブランチでの名前: CP2
- 描く仕組み（低遅延・面・履歴・予測）は本家と同じ。変わるのは見える物と一部の動きだけ。切り替えても絵・履歴・道具・色はそのまま。

## 地図（`src/paint.js`）

  - `setUi(on)`: 版を切り替える。順に endStroke → ページ操作モードを外す → CP2_TOOLS でなければペン → swapPen → layout → layBar → バーの位置（動かしていなければ placeBar で置き直す）→ updateGhost → remember → お知らせ

    - hideCB（Simple の閉じる）

## 不変条件（壊すと困る）

- バーとその他に並べるのは layout() だけ。ボタンや項目を足すときは、本家と Simple のどちらに出すかを決めて layout の並びに入れる（本家のその他は mainMore）。
- Simple では say() は fn がないと何も出さない。Simple で知らせたいことはボタン付きにする。
- Simple の間は、本家のペンの太さ・濃さ・種類が mainPen にあり、CFG.pen は 5・1、penType は 'pen'。
  - snapPrefs は mainPen の方を返す。
  - CFG.pen や penType を直接読み書きする処理を足すときは、Simple の間かどうかに気をつける。
  - swapPen は、setUi と起動の設定の後以外では呼ばない。
- 2 本指のリスナーは capture で登録する。bubble で足すと onDown の後に呼ばれ、1 本目の線が描き始まってしまう。layout が版で付け外しするので、本家の入力の経路には何も増えない。
- 「本家に戻す」は Simple のその他にいつも出す（DEF.ui = 'cp2' で始めた人が戻れなくならないように）。

## 決定事項と理由

- **移し方（T-088）。** 本家の中の表示の版として移した。
  - 別のコード（CP2 ブランチの paint.js）を埋め込んで入れ替える案は、次の理由で採らなかった:
    - 絵が引き継げない
    - ブックマークレットが倍になる
    - CP2 側が古い予測（T-060・T-087 の前）のままになる
  - 移したのは CP2 の画面と動きだけ（「本家との違い」の表）。
- **置き場所と覚え方（T-088、ユーザーが選んだ）。**
  - 置き場所: 「開発用を入れたらその他に現れる、お試し〈Preview〉」。T-101 でユーザーが「開発用限定から外して、名前を Simple Preview にする。一歩前進」と決め、本家のその他の最後にいつも出し、インストールページの最初に出す版もふつうの設定にした
  - 覚え方: 「インストールページで既定も選べる＋サイトごと」
  - 切り替えたらボタン付きのお知らせ（本家に戻す）を出す。
- **切り替えたときの道具（T-089、ユーザーの要望）。** Simple のバーにない道具のまま切り替えたらペンにする。
  - どのボタンも選ばれていない見た目にしないため。
  - setTool('pen') を通すので、浮いている選択も確定される。
  - 起動したときと、Simple の中でキーで選んだ道具は変えない。
- **呼び名（T-090、ユーザーの要望: 一旦 Simple に）。**
  - メニュー・お知らせ・インストールページ・Paint ボタンの名前（Paint Simple）を「Simple」にそろえた。
  - T-101 で、画面の呼び名を「Simple Preview」（括弧なし）にした。Paint ボタンの名前は Paint Simple のまま。
  - コードと設定の値は cp2 / ui: 'cp2' のまま。サイトに覚えた設定がそのまま効く。
- **ペン（T-091・T-093・T-097、ユーザーの要望: デフォルト絶対で、本家に影響されないように。種類も固定）。**
  - 普通のペン・太さ 5・濃さ 100% に固定した。
  - CP2 ブランチの太さ 6 と違い、5 はユーザーの指定。
  - Simple の中で [ ] で変えた太さは覚えない（次に Simple にすると 5）。
- **ペンボタンの色（T-096・T-098・T-100、ユーザーの「試してみたいこと」）。** Simple には色のボタンがないので、ペンボタンで今の色を見せる。
  - T-096・T-098 は下線（.pc::after、3px）。ボタンの中に 1px の縁付き → ボタンのすぐ下に縁なし・ペンのときだけ（ユーザーが画像で示した形）。縁がないと明るい見た目の白・暗い見た目の黒が溶けた。ユーザーが「やめよう。最後に、あなたのセンスで色を付けようとしてみて」と言った。
  - T-100（Claude の案）: ペンを選んでいるときの青い地を、今の色にする（`.b.on.pc`。色見本のように見える）。印は相対輝度 0.3 を超える色（白・黄・橙）で黒、ほかは白（isLite。applyLook の好きな色と同じ計算）。影（0 1px 3px #0000003d）で浮かせ、明るい見た目の白でも白い鍵のように分かる。囲む線は使わない。重ねても押しても色のまま（.b.on:not(.c):hover の濃い青より後に、同じ強さ以上の規則を置いた）。
  - 試作で、アイコンの中（ペンの胴）を塗る案も並べた。中の幅が 2px ほどしかなく、青い地に青が見えないので捨てた。
  - 青（#1e88e5）は、消しゴムのときの青い地（#3d7cff）と近い。印（ペン／消しゴム）で見分ける。
  - お試し。やめるときは CSS の `.b.on.pc,…` の 1 行、markPen の `.pc` の 1 行、setColor の `--pc`・`--pi` の 2 行を外す（isLite は applyLook が使うので残す）。T-100 のテストも外す。
- **その他を引いても閉じない（T-094、ユーザーの要望）。** Simple のパネルはその他だけで、色を選ぶ場所なので、本家の色と太さのパネルと同じ扱いにした。

## 落とし穴

- 切り替えた直後は、ボタン付きのお知らせ（4 秒）が出ている。Simple で「お知らせが出ない」を確かめるテストは、先にそれが消えるのを待つ（一度これで落とした）。
- 文字の入力欄・薄い答えは、wrap の中でツールバーより前に置く（T-092。後ろに足すと開いたパネルより手前に出る）。Simple のその他（色）を、入力中の文字の上で開いたときに見つかった。本家も同じ（HANDOFF.md の不変条件）。
- テストで Simple のバーのボタンを押すときは、`.bar > [aria-label^="ペン"]` のように `.bar >` を付ける。Simple のペンのボタンは消しゴムのとき「消しゴム」になる。
